# 自动配队计划

本文记录战斗系统中「配队」相关能力的规划。**目前尚未实现**，现阶段只支持固定配队。

## 现状：固定配队

- 方案文件的 `team` 字段只用于开战前提示（同一配置每个进程提示一次），不识别、不校验实际站位。
- 「角色与轮转」设置可以按槽位覆盖名称、备注、出招、站场时间，禁用槽位，调整首发与轮转顺序（见 [战斗系统](./combat.md#有效方案)）。这些都是用户声明：名称不等于识别到的角色，禁用槽位只是不主动切入，不会去游戏里换人。
- 引擎只认槽位号：队伍人数由用户在「战斗配置」中手动选择，超出人数或被禁用的槽位开战前移出轮转；切人确认失败（空槽/阵亡）的槽位本场移出轮转。
- 战斗接口只负责出招控制，不提供配队检查。

## 分阶段计划

### 阶段 1：队伍人数与空槽识别

- 识别右侧队伍栏的槽位数字（参考 ok-NTE `char_N_text`，720p 约 x=1249、y=162/250/338/426），得到队伍人数。
- 引擎开战前直接把空槽移出轮转，取代目前「队伍人数」的手动设置（过滤逻辑 `engine.effective_order` 与禁用槽位 `disabled_slots` 已就绪）。

### 阶段 2：角色识别

- 用右侧头像做模板匹配（参考 ok-NTE `box_char_N`：720p x=1187、w=30、h=39，y=140/228/316/404；椭圆 mask + TM_CCOEFF_NORMED ≥ 0.6）。
- 头像模板需在 1280×720 下重新截取；角色名录与 `Character_UI/Character_Pic` 保持同源。
- 识别结果写入 `Snapshot`，方案的 `team[].character` 可与识别结果比对。

### 阶段 3：配队检查接口

- 新增 `check_team(context, scheme) -> TeamCheckResult`，比对方案声明与实际队伍，返回缺失/错位的槽位。
- 全局战斗配置增加「开战前检查队伍」开关：不符时提示并按策略处理（继续 / 停止任务）。
- 方案 `team` 字段从「仅提示」变为「可校验约束」，格式保持向后兼容。

### 阶段 4：自动编队

- 通过 SceneManager 进入编队界面（需新增 `InTeamMenu` 场景与 `__ScenePrivate*` 导航节点），按方案 `team` 依次选择角色，每步识别确认。
- 对外提供 Pipeline 接口 `CombatApplyTeam`，全局战斗配置增加「战斗前自动编队」开关。

### 阶段 5：按角色绑定出招表

- `combos` 支持以角色名为键（如 `"零": "..."`），按识别结果选择出招表；槽位键与 `default` 仍作为回退。在此之前，可用「角色与轮转」的逐槽出招，或脚本会话 `session.perform(combo, slot=n)` 手动绑定。

## 约束

- 识别失败时一律退回固定配队行为，不阻塞战斗。
- 自动编队只改队伍组成，不涉及角色养成、装备等其他界面。

## 暂缓的战斗能力

以下能力不在本期范围，待配队能力稳定后再评估：

- **E/Q 可用性识别**：E 图标 `[1100, 638, 36, 19]`、Q 图标 `[1191, 638, 36, 19]` 内亮像素（RGB ≥ 244）判断点亮，配合 CD 数字 OCR（数值来自 ok-NTE 换算，需实机 720p 校准）。
- **DSL 条件分支**：在可用性识别之上支持 `if skill: ... else: ...`（ok-NTE 语法），编译器目前对 `if` 报 `unsupported_statement`。
- **评分切人**：按动作标签、站场偏好、切人冷却打分，替代固定 `order`。
- **角色专属预设**：依赖阶段 2 的角色识别和 E/Q 可用性识别（角色流程需要判断技能是否放出），在此之前内置方案保持通用写法。
- **音频闪避接入**：复用 `SoundTrigger`，在 `Runtime.sleep` 的切片中插入闪避动作。
- **进战/脱战信号**：已实现血条形状、敌人等级、Boss 等级的多证据判定、撤离提示暂停，以及调用方 `signal_nodes`（见 [战斗系统](./combat.md#生命周期)）。待做：等级/Boss/形状参数的实机校准与截图回归集、开放世界通用的胜利/脱战画面识别。
- **阵亡与复活处理**：识别复活界面，团灭后的恢复流程。
